# Zenn 記事の下書き生成

ユーザーから渡されたアウトライン・主張・根拠データをもとに、CLAUDE.md のスタイルガイドに従って `articles/` に記事の下書きを作成します。

## 手順

### 1. 素材の確認

ユーザーから渡された素材を整理します:

- **アウトライン**: 記事の流れ・見出し構成
- **主張**: この記事で言いたいこと(1つに絞れているか)
- **根拠データ**: 検証結果、ベンチマーク、コード、参考リンクなど

以下が不明な場合は AskUserQuestion で確認してから書き始めます:

- 想定読者(初心者向け / 実務者向け / 特定技術の利用者)
- 記事の目的(問題解決 / 検証報告 / 知見共有)
- ボリューム感(既存記事は 100〜140 行程度が標準)

### 2. タイトルと emoji の提案

本文を書く前に、**タイトル案を 3〜5 個** emoji 案とセットで提案し、ユーザーに選んでもらいます。

タイトルの条件:

- 具体性がある(数字、固有名詞、結果を入れる)
- 意外性や問いかけで目を引く(例:「UUIDを重複させるにはどれだけ時間がかかるのか試してみた」)
- 内容と一致している(釣りタイトルにしない)
- 「〜してみた」「〜する方法」「爆速で〜」など既存記事のトーンに合う形

### 3. 記事ファイルの作成

`articles/<slug>.md` を作成します:

- slug は内容を表す英小文字ケバブケース、**12〜50 字**(a-z0-9 とハイフン・アンダースコア)
- frontmatter は CLAUDE.md の規約に従う。**`published: false` 必須**

### 4. 本文の執筆

CLAUDE.md のスタイルガイド(カジュアルな敬体・一人称の実体験ベース・構成の型)に従って執筆します。特に:

- **冒頭で価値を伝える**: 最初のセクションで「誰向けか・何がわかるか」が伝わるフックを書く。問いかけ見出しや `:::message` を活用
- **主張とデータを対応させる**: 主張ごとに渡されたデータを根拠として配置する
- **捏造禁止**: 渡されたデータにないことは書かない。足りない箇所は `<!-- TODO: ○○のデータ・検証が必要 -->` を残す
- **視覚的な緩急**: コードブロック(言語指定つき)、テーブル、`:::message`、リンクカード(URL 単独行)で単調にならないようにする

### 5. lint

`npx textlint articles/<slug>.md` で作成した記事だけを lint し、指摘を修正します(文意が変わる場合はユーザーに確認)。

### 6. 報告

最後に以下を報告します:

- 作成したファイルパスと記事の構成サマリ(見出し一覧)
- 残した `TODO:` コメントの一覧と、ユーザーに確認・追加してほしいデータ
- `make preview` でプレビューできること
