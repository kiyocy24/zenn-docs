# Zenn 記事のレビュー

指定された記事(引数がなければ `git status` / 更新日時から最後に変更された `articles/*.md`)を読み、読みやすさと訴求力の観点でレビューします。

## レビュー観点

### 1. タイトルと導入(目を引くか)

- タイトルだけ見て読みたくなるか。具体性(数字・固有名詞・結果)があるか
- 冒頭 3〜5 行で「誰向けか・何がわかるか」が伝わるか
- 改善余地があれば**代替タイトル案を 2〜3 個**提示する

### 2. 構成

- 見出しだけを拾い読みして記事の流れがわかるか
- 「フック → 本編(手順/検証) → 解説 → まとめ/参考リンク」の型に沿っているか
- 1 セクションが長すぎないか(目安: スクロール 1〜2 画面)

### 3. 読みやすさ

- 一文が長すぎないか(目安 120 字)、冗長表現がないか
- 文体が一貫しているか(カジュアルな敬体。CLAUDE.md のスタイルガイド参照)
- こそあど言葉・主語の省略で意味が取りにくい箇所がないか

### 4. 主張と根拠

- 主張に対応するデータ・検証結果が示されているか
- 出典・参考リンクが必要な箇所に付いているか
- `TODO:` コメントが残っていないか(公開前チェックとして)

### 5. Zenn 活用度

- コードブロックに言語指定があるか
- URL 単独行のリンクカード、`:::message`、テーブルを効果的に使えているか
- frontmatter が規約通りか(emoji、topics、published)

## 機械チェック

`npm run lint`(textlint)を対象ファイルに実行し、指摘を結果に含めます。

## 出力形式

指摘は 3 段階に分けて報告します。**勝手に本文を書き換えず**、ユーザーが直したい項目を選んでから修正します:

- **Must**: 公開前に直すべき(事実誤認の疑い、根拠なし主張、TODO 残り、壊れたリンク)
- **Should**: 直すと読みやすさ・訴求力が上がる(構成、タイトル、導入、冗長表現)
- **Nice**: 好みの範囲(言い回し、表記ゆれ)

各指摘には該当箇所(見出し名や引用)と修正案を添えます。
